# shogi-analyzer

将棋ウォーズの棋譜をローカルで解析する。棋神解析の自前版。課金なし・通信なし。

## 使い方

```bash
# ── ビューア（盤面＋評価値グラフ）をつくる ──
python3 add.py                                    # クリップボードのKIFを取り込む
python3 export.py games/20260901_1056.kif         # 解析して out/*.json
python3 build.py  out/20260901_1056.json          # out/*.html （ブラウザで開ける）
open out/20260901_1056.html
```

```bash
# ── CLIで数字だけ見る ──
# 1局まるごと（全手の評価値・損失・最善手・読み筋）
python3 analyze.py games/20260830_0023.kif

# 特定の局面だけ深く読む
python3 analyze.py games/20260830_0023.kif --at 34 --movetime 5000 --pv 12

# 1手あたりの探索時間を伸ばす（既定 1000ms。70手で約1分）
python3 analyze.py games/xxx.kif --movetime 3000
```

出力例:

    ↑手数 ↑指し手        ↑評価値  ↑損失  ↑最善手         ↑読み筋

## 棋譜の取り込み

1. 将棋ウォーズの**棋譜再生画面の上部にあるコピーアイコン**を押す（KIF形式がクリップボードに入る）
2. Macで `python3 add.py`

これだけ。ファイル名は棋譜の開始日時から自動で決まり（`games/20260830_0023.kif`）、
そのまま `verify.py` の検算まで走る。画像認識は不要。

iPhoneでコピーしたものをMacで貼るには、ユニバーサルクリップボード（Handoff）が要る。
うまく渡らない場合は、棋譜テキストを直接 `games/なまえ.kif` に保存してもよい。

## 🚨 新しい棋譜は、まず検算を通すこと

```bash
python3 verify.py games/新しい棋譜.kif
python3 verify.py games/新しい棋譜.kif --at 34   # 盤面を出して画面と見比べる
```

**Stockfish系は `position startpos moves ...` に不正な手が混ざると、エラーを出さずに
そこまでで適用を打ち切る。** 変換にバグがあっても、途中までの局面について
「それらしい評価値」が返ってくるので、解析結果を眺めても絶対に気づけない。
`verify.py` はエンジンが報告する手数が期待値と一致するかを見て、これを検出する。

## 構成

| ファイル | 役割 |
|---|---|
| `add.py` | クリップボードのKIFを取り込む（検算まで自動） |
| `kif.py` | KIF → USI 変換。依存ライブラリなし |
| `engine.py` | USIエンジンのドライバ |
| `analyze.py` | 解析本体（CLI出力） |
| `export.py` | 解析してビューア用JSONを吐く |
| `viewer_template.html` | ビューアのテンプレート（`/*__DATA__*/` にJSONが入る） |
| `build.py` | テンプレート＋JSON → 単体HTML。`--bare` でArtifact公開用 |
| `verify.py` | KIF→USI変換の検算 |
| `games/` `out/` | 棋譜置き場 / 出力 |

### ビューアの設計メモ

- 盤は**榧の盤・黄楊の駒**の色から起こしている（`--board` `--koma` 系のトークン）。
  木目は薄い縞のグラデーションを2枚重ねただけで、写真テクスチャは使っていない。
  星（4つの交点の点）も打ってある。駒は五角形のまま、成駒は朱
- 🔑 **盤のマス目は `grid-template-rows:repeat(9,1fr)` が要る**。
  これが無いと段の高さが中身に引きずられ、**駒のある段だけ背が高くなる**（46px vs 26px）。
  盤全体は `aspect-ratio:1` で正方形に見えるので、目視では気づきにくい
- 配色は先手＝藍 `#1D6FB8` / 後手＝朱 `#C0402F` / 強調＝金 `#B8892B`。
  色覚特性を含む検証を通してある（ライト・ダーク両方でPASS）
- **悪手は色だけでなく将棋の記号 `?!` `?` `??` でも示している**（色に頼らない）
- 🔑 **評価値の縦軸はtanhで圧縮している**。大半の手が±400に収まり終盤だけ跳ねるので、
  線形軸だと序盤〜中盤が一本の平らな線に潰れて読めない。目盛りは評価値のまま打っている
- 読み筋は盤面から駒を引いて日本語表記に直している（`7g7f` ではなく `▲7六歩(77)`）。
  そのためにUSIの指し手を盤面に適用する処理を持っている（成り・駒取り・打ちに対応）

## パーサーの未検証部分

`games/20260830_0023.kif` にたまたま出てこなかったので、以下の表記はまだ実棋譜で
動かしていない。**遭遇したら `KifError` で落ちる設計**（黙って誤変換するより良い）なので、
落ちたら想定内のギャップとして直すこと。回帰ではない。

- `同　歩(76)` … 直前手と同じ地点への移動
- `７七桂不成` … 成らずを明示する表記
- `５七成銀(48)` … 成駒が駒名として現れる形（`と`・`馬`・`龍` は実装済み）

## エンジン

`fairy-stockfish`（Homebrew: `brew install fairy-stockfish`）を使う。
USIプロトコルに対応していて、`UCI_Variant=shogi` で将棋になる。Apple Siliconでそのまま動く。

### ⚠️ いまは NNUE ではなく classical 評価で動いている

`EvalFile` が空なので、エンジン起動時に `info string classical evaluation enabled` と出る。
つまり**評価関数を積んでいない状態**。

- **300〜500点級の悪手を拾う用途には十分**（このツールの主目的はそこ）
- **「+61」のような細かい数字を額面どおり受け取ってはいけない**。互角の局面で
  ±100点程度の誤差は普通に出る

精度を上げたいなら、やねうら王＋水匠(NNUE)に差し替える。`--engine` でパスを渡すだけ。
ただし**評価関数ファイルとエンジンのNNUEアーキテクチャが一致していないと、
エラーではなく無言でおかしな評価値を返す**ので、差し替えたら既知の局面で答え合わせすること。

## 実装上の注意（ハマった点）

- 🔑 **パイプに `go` と `quit` をまとめて流すと探索が即打ち切られる。**
  `bestmove` を読むまでプロセスを開いたままにすること（`engine.py` がやっている）
- 🔑 **USI の `score cp` は「手番側から見た」値。**
  そのままグラフにすると先手と後手が交互に勝っているようなギザギザになる。
  後手番の局面では符号を反転して、全部「先手視点」に揃えている
- 🔑 **詰み(`score mate N`)を大きな点数に変換したまま引き算すると、損失が9万点になって壊れる。**
  損失計算の前に評価値を ±`--clamp`(既定2000) に丸めている。
  「もう決着している局面での上下」は損失として数えない、という考え方
- KIF は移動元が括弧で入っている（`６八銀(79)`）ので、盤面を再現しなくても変換できる。
  `成` が末尾なら成る動作、先頭なら成駒の駒名（`成銀`）、`不成` は成らない、で判別している

## 検算

`games/20260830_0023.kif` は**70手目に後手(christel09)が投了**した将棋。
解析結果が終盤にかけて先手優勢（+4000〜詰み）に振れていれば符号の向きが正しい。
逆に後手優勢と出たら、どこかで視点の反転が抜けている。

## やっていないこと

- 候補手を複数出す（`setoption name MultiPV value 3` を足せば可能）
- 定跡・囲いの判定
- 複数局をまたいだ集計（持ち時間別の平均損失の推移など）

## 注意

**対局が終わったあとの検討にのみ使うこと。** 対局中に見るのはソフト指しで、
将棋ウォーズの規約違反かつBAN対象。
